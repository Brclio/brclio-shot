# Brclio Shot 安全策略

## 支持版本

| 版本 | 安全修复 |
| --- | --- |
| 最新 `0.1.x` | 支持 |
| 更早版本 | 不支持 |

项目进入后续 minor 版本后，本表会随支持窗口更新。

## 报告漏洞

请不要在公开 Issue 中提交未修复漏洞、截图样本、个人文件路径、证书、Cookie 或其他敏感数据。

优先使用 GitHub 的私密漏洞报告：

<https://github.com/Brclio/brclio-shot/security/advisories/new>

报告中请包含：

- Brclio Shot 版本、操作系统版本与 CPU 架构；
- 可复现的最小步骤及预期/实际结果；
- 漏洞影响与所需前置条件；
- 已做脱敏的日志、崩溃栈或概念验证；
- 是否已在其他位置公开。

请给维护者合理的确认和修复时间。修复发布前不要公开可直接利用的细节。

## 数据处理边界

### 留在设备上的内容

区域、窗口、当前屏幕、延时与手动滚动长截图的像素处理在本地完成。编辑器、贴图、剪贴板、文件编码和历史也在本地运行。项目不包含遥测、用户账号、云同步或截图上传服务。

本地历史位于 Electron `userData/history` 下，包含 PNG 原图、JPEG 缩略图和 JSON 索引。设置保存在 `userData/settings.json`。这些文件继承当前操作系统用户权限，不提供额外加密；设备磁盘、账户或备份被他人访问时，截图也可能被读取。敏感环境应关闭历史并使用系统磁盘加密。

### 会产生网络请求的内容

“网页整页截图”会访问用户输入的 HTTP/HTTPS URL。目标站点及其中的子资源可获得正常网络访问中可见的信息。临时网页会话：

- 使用随机隔离 partition，不共享日常浏览器登录态；
- 拒绝权限请求、下载与弹出窗口；
- 启用 renderer sandbox、context isolation 和 web security；
- 捕获结束后销毁窗口与会话引用。

这降低会话混用风险，但不把不可信网页变成可信内容，也不提供匿名、VPN、恶意站点扫描或内容净化保证。不要为捕获目的向未知页面输入账号、密码或机密信息。

应用“关于”页中的允许链接会交给系统默认浏览器打开。

## 应用信任边界

- Renderer 不启用 Node Integration。
- 生产 UI 只从 `brclio://app` 只读协议加载，协议处理器限制固定资源根目录并拒绝目录穿越。
- Preload 只暴露固定、带类型的 IPC 方法。
- 主进程对 IPC 发送窗口和截图请求字段进行检查。
- 远程网页不加载应用 preload，不获得 Brclio Shot IPC。
- 保存路径和“显示文件”操作在主进程限制；默认保存不会覆盖已有文件。
- 图像解码、单帧尺寸、累计输入与输出像素有上限，用于限制意外内存消耗；这不是面对主动恶意输入的完整资源隔离。

## 屏幕权限

macOS 屏幕录制权限由系统管理。Brclio Shot 只在用户请求截图/授权时访问桌面来源；拒绝后可打开对应系统设置页面。Windows 下通常不需要同类授权。无论平台，其他应用的敏感内容都可能出现在用户主动选择的截图中，使用者负责确认分享范围。

## 构建与发行信任

GitHub Actions 使用锁文件和 `npm ci` 构建。每个 tag Release 生成 `SHA256SUMS.txt`。哈希只能验证下载文件与该 Release 是否一致，不能代替发布者代码签名。

没有平台签名密钥时，workflow 生成并上传不受平台信任的开发包：

- macOS 使用 ad-hoc 开发签名以保证包可以启动，但没有 Apple Developer ID 或公证票据，仍可能显示 Gatekeeper 警告；
- Windows 可能显示 SmartScreen“未知发布者”；未签名包没有 Authenticode 发布者身份。

正式分发前应配置并验证 macOS Developer ID 签名/公证与 Windows Authenticode 签名。具体秘密变量和验证命令见[发布说明](RELEASING.md)。任何 Release 都应根据实测结果标注签名状态，不能仅凭 workflow 成功推断已经签名。

## 不在 v0.1 保证内

- 针对已入侵操作系统、管理员账户或同用户恶意进程的防护；
- 对截图内容进行端到端加密或安全擦除；
- 对用户输入 URL 的信誉判断、反钓鱼或恶意内容扫描；
- DRM、受保护系统表面或浏览器防截屏策略绕过；
- 自动更新供应链。
